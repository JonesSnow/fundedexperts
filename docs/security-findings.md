## HIGH (2)

### H-1: Encryption Decryption Dead Code
- **Component:** lib/encryption.ts
- **Finding:** `decrypt()` function exists and is tested, but is NOT called by any API route handler. Credentials can be encrypted but never decrypted in the API layer.
- **Evidence:** `grep -r "decrypt(" app/ lib/` — no matches in route handlers
- **Impact:** If credentials are needed for MT5 terminal connection (bridge, monitoring), they cannot be retrieved from the database through the API. This means either: (a) the credential lifecycle is incomplete, or (b) decryption is intended only for a separate worker service that doesn't exist yet (lib/monitoring/ doesn't exist).
- **Fix:** Either implement decryption in a separate worker service (planned but not built) or document that credentials are write-only via API.
- **Severity Justification:** High because encrypted credentials that cannot be decrypted are effectively lost — if wrong credentials are stored, they cannot be corrected through the API without deleting the account.
- **Regression Test:** Verify that no API route calls `decrypt()` (test in mt5-accounts.test.ts can be extended).

### H-2: Middleware Does Not Check Account Status
- **Component:** middleware.ts
- **Finding:** The middleware checks JWT validity for /admin/* and /dashboard/* paths but does NOT check whether the trader account is SUSPENDED or INACTIVE. A suspended/inactive user can navigate to admin pages in the browser before being rejected by an API call.
- **Evidence:** middleware.ts lines 4-26 — checks `getSession(token)` but not `trader.status`
- **Impact:** A user with a valid JWT but SUSPENDED/INACTIVE status can access the React pages for /admin and /dashboard. They will be rejected on API calls but may briefly see admin UI before redirecting. This could expose admin UI structure.
- **Fix:** Add status check in middleware or in the page components' server-side logic.
- **Regression Test:** Verify that middleware redirects SUSPENDED/INACTIVE users attempting to access /admin/*.

## MEDIUM (5)

### M-1: Logout Does Not Invalidate JWT
- **Component:** app/api/auth/logout/route.ts, lib/auth/session.ts
- **Finding:** Logout clears the session cookie but does NOT invalidate the JWT token server-side. Because JWTs are stateless, a logged-out user's token remains valid until expiry (7 days).
- **Evidence:** logout route only clears cookie; session.ts has no token blacklist
- **Impact:** If a user's device is compromised, an attacker can use the JWT for up to 7 days even after the user logs out.
- **Fix:** Implement a token blacklist (requires Redis or database table) or reduce JWT expiry.
- **Regression Test:** Verify that a JWT used after logout still works (documented limitation, not a defect to fix without Redis).

### M-2: No Content-Type Validation
- **Component:** All POST/PUT route handlers
- **Finding:** POST and PUT endpoints do not validate Content-Type header. A request with `Content-Type: text/plain` containing JSON string body will be accepted because `request.json()` doesn't check Content-Type.
- **Evidence:** All route files use `await request.json()` without Content-Type check
- **Impact:** Minor — could cause unexpected behavior if non-JSON content is sent. Next.js `request.json()` attempts to parse regardless of Content-Type.
- **Fix:** Add Content-Type check at the start of POST/PUT handlers or in middleware.

### M-3: POC Directory Not Initially Excluded from Git
- **Component:** .gitignore
- **Finding:** The `poc-mt5-bridge/` directory was not in .gitignore during initial creation. It now contains test artifacts (poc-results.json, test scripts).
- **Evidence:** Initial git status showed `?? poc-mt5-bridge/`
- **Impact:** Low — no secrets were committed. POC results contain no sensitive data.
- **Fix:** Added `poc-mt5-bridge/` to .gitignore in Phase 8.

### M-4: Generic Error Messages in API Routes
- **Component:** All API routes
- **Finding:** Error responses use generic messages like "Failed to create account", "Failed to fetch account", "Failed to delete account". These don't help legitimate users debug but also don't expose internal details.
- **Evidence:** Every catch block returns `{ success: false, error: "Failed to ..." }`
- **Impact:** Medium for developer experience, Low for security. Internal details are NOT exposed (good), but debugging is difficult.
- **Fix:** Add structured error codes (e.g., `{ error: "CREATE_FAILED", details: "..." }`) for debugging.

### M-5: next-env.d.ts Not in .gitignore
- **Component:** .gitignore
- **Finding:** `next-env.d.ts` and `.next/types/` are auto-generated by Next.js and not in .gitignore.
- **Evidence:** Found in repository root, tracked by git
- **Impact:** Low — auto-generated file, may cause merge conflicts.
- **Fix:** Add to .gitignore.

## LOW (5)

### L-1: Rate Limiting Is Process-Local
- **Component:** lib/auth/rate-limit.ts
- **Finding:** Rate limiter uses a module-level `Map`. Does not persist across server restarts, server crashes, or scale across multiple instances.
- **Evidence:** Line 6: `const attempts = new Map<string, RateLimitEntry>()`
- **Impact:** After a server restart, all rate limit counters reset to zero. Under load balancing, each instance has its own counter.
- **Fix:** Use Redis or database-backed rate limiting for production. Documented in docs/authentication.md.

### L-2: Session Route Indistinguishable Responses
- **Component:** app/api/auth/session/route.ts
- **Finding:** Returns `{ authenticated: false }` for both "no session" and "suspended/inactive user" cases. Clients cannot distinguish between unauthenticated and unauthorized.
- **Evidence:** Lines 9-16 and 30-31 both return `{ authenticated: false }`
- **Impact:** Low — UI treats both as "not logged in", which is correct behavior. But API consumers cannot tell if a session exists but is inactive.
- **Fix:** Consider returning `{ authenticated: false, status: "none" | "suspended" | "inactive" }`.

### L-3: Duplicate Email Error Message
- **Component:** app/api/auth/register/route.ts
- **Finding:** Returns "Email already registered" for duplicate registration (line 47). This confirms email existence to attackers (user enumeration).
- **Evidence:** Line 47 in register route
- **Impact:** Low — standard UX tradeoff. Many applications do this for usability.
- **Fix:** Could return generic "Registration failed" but this harms UX. Document as known limitation.

### L-4: PrismaClient Per-Route Instantiation
- **Component:** All API route files
- **Finding:** Each route file creates `new PrismaClient()` at module scope. In Next.js serverless, this can lead to connection exhaustion under load.
- **Evidence:** Every route file has `const prisma = new PrismaClient()`
- **Impact:** Medium for scaling. Not a security issue.
- **Fix:** Use PrismaClient singleton pattern (e.g., global prismadb pattern).

### L-5: Unused Imports in Several Files
- **Component:** Various route files
- **Finding:** Several files import functions/types that are unused (e.g., `RulesetVersion` in publish route, `Product` in products route, `Ruleset` in rulesets route).
- **Evidence:** ESLint warnings (32 warnings)
- **Impact:** Very low — no security or correctness impact. Just code cleanliness.
- **Fix:** Remove unused imports.

## INFORMATIONAL (3)

### I-1: No Account ID Ownership Check
- **Component:** app/api/accounts/[id]/route.ts, status, health routes
- **Finding:** Account routes operate on any account ID reachable by ADMIN. This is expected behavior (admins should manage all accounts) but should be documented.
- **Impact:** None — admin role implies full access.

### I-2: SESSION_COOKIE Constant in Tests
- **Component:** tests/auth.test.ts
- **Finding:** `SESSION_COOKIE` is tested as `"session"` rather than testing the actual constant from session.ts.
- **Impact:** None — test correctly validates the value.

### I-3: Environment Variables Documented but Unused
- **Component:** .env.example
- **Finding:** MT5_API_URL, MT5_API_KEY, MT5_API_SECRET, REDIS_URL, and SMTP settings are documented in .env.example but not referenced in any source file.
- **Impact:** None — documentation is forward-looking for future features.
